# 고장 분석표

고장 종류는 이 표에서 고른다. 고장마다 "지금은 무엇이 막나 → 내가 더하는 것 → 어떻게 시험하나"를 적는다.

Nav2와 그 방어 장치는 노트북에서, 드라이버(turtlebot3_node)는 로봇에서 돈다.

## 명령 · 보드

| 번호 | 고장 | 영향 | 지금은? 시뮬(Gazebo) | 지금은? 실물(원래 드라이버) | 내가 더하는 것 | 시험 |
| --- | --- | --- | --- | --- | --- | --- |
| F2-a | controller만 종료 | 명령이 끊긴다 |  |  | 없음(이미 있는 장치를 확인만 한다) | 시뮬 · 실물 비교(실물 Nav2와 함께) |
| F2-b | Nav2 전체 종료 | 로봇이 마지막 속도로 계속 간다(F2-w와 같은 길이라 소스로만 확인) |  |  | 드라이버의 명령 시간 초과(패치) | 소스로 확인(시험은 F2-w로 대신한다) |
| F2-w (고장 ①) | 노트북 Wi-Fi 끊김 · teleop 강제 종료 · `fault_injector`로 끊기 | 로봇이 마지막 속도로 계속 간다 |  |  | 드라이버의 명령 시간 초과(패치) | 시뮬 · 실물(받침대 · 바닥) |
| F3 | 노트북 → 로봇 명령의 지연 · 손실(`fault_injector` · `tc netem`), Wi-Fi 혼잡(`iperf3`), 로봇 CPU 부하(`stress-ng`) | 시간 초과를 짧게 잡으면 잘못 멈춘다 |  |  | 시간 초과 값을 분포로 정한다 | 실물(받침대 · 바닥). 시뮬은 도구 검증용 |
| F5 (고장 ②) | OpenCR USB 연결 끊김 · 읽기 실패 | `/joint_states` · `/odom`이 낡은 값을 새 시각으로 계속 낸다(소스로 확인) | 해당 없음(시뮬에는 이 드라이버와 보드가 없다) |  | 마지막 읽기 성공 시각 감시(패치) | 실물(받침대) |
| F5-rc | ros2_control로 돌릴 때 USB 끊김(hardware interface의 read 실패) |  | 해당 없음 |  | 없음(이미 있는 장치와 모터의 Bus Watchdog을 확인하고 F5의 패치와 견준다) | 실물(받침대. 구동 · 드라이버 갈래) |
| F0 | turtlebot3_node 자체가 종료 | 명령을 전할 곳이 없다 | 해당 없음 |  | 없음(이미 있는 장치를 확인만 한다) | 실물(받침대, 영상으로. 노드가 죽으면 `/joint_states`도 사라져 rosbag으로는 못 잰다) |

## 통신

| 번호 | 고장 | 영향 | 지금은? 실물 | 내가 더하는 것 | 시험 |
| --- | --- | --- | --- | --- | --- |
| N2 | 통신이 나빠짐(약한 신호 · 붐빔 · 로봇 CPU) | 명령이 늦고 띄엄띄엄 온다. 이때 끊기면 정지 거리가 길어진다(추정) |  | 통신 상태를 `/diagnostics`로 알림(`link_monitor`) | 실물(집 안 순찰 포함) |

아래는 이번 범위 밖이다.

| 번호 | 고장 | 이유 |
| --- | --- | --- |
| F1 | LiDAR(`/scan`) 끊김 | 드라이버 쪽 고장 두 가지에 집중한다(센서 끊김 감시는 다른 팀 프로젝트에서 다뤘다) |
| F4 | 위치 튐(로봇을 들어 옮김) | 위치 추정을 다뤄야 해서 범위가 커진다 |
| N1 | Wi-Fi가 끊겼다 다시 붙을 때 명령이 다시 오기까지 | 이번 범위에서는 통신 감시까지만 한다. 한다면 RMW마다 다시 붙기까지의 시간을 잰다 |
| N3 | 여러 대가 같은 Wi-Fi에서 서로를 찾을 때 | 로봇이 한 대다. 한다면 가짜 노드 묶음으로 흉내 내어 발견 트래픽을 잰다 |
| N4 | 공유기 사이를 옮겨 다닐 때(로밍) | 집에 공유기가 하나다 |

## 고장 상태

전이표를 쓸 때 함께 정한다: 시작 직후(명령도 읽기도 아직 없을 때)의 상태, 두 고장이 겹칠 때 어느 쪽이 먼저인지, 정상으로 돌아오는 데 필요한 새 명령의 수와 시간(1개면 망이 나쁠 때 섰다 갔다를 되풀이할 수 있다). 다루지 않기로 하면 이유를 적는다. 통신이 나빠진 상태(N2)는 드라이버의 전이표가 아니라 `link_monitor`가 따로 알린다.

| 상태 | 들어가는 조건 | 로봇이 하는 일 | 나오는 조건 |
| --- | --- | --- | --- |
| 정상 | | 명령대로 움직인다 | |
| 명령 끊김 | | 바퀴를 세우고 `/diagnostics`에 알린다 | |
| 보드 끊김 | | 낡은 값을 내보내지 않고 `/diagnostics`에 알린다 | |
