# 요구사항 (1쪽)

- 이 요구사항은 이 프로젝트에서 스스로 정한 것이고 제품 안전 요구사항이 아니다.
- 숫자마다 근거를 적는다. 근거 없는 숫자는 "가정"으로 표시하고 실측 뒤에 고친다.
- 시계: 판단(드라이버 코드)은 **단조 시계**, 측정은 **로봇 rosbag의 받은 시각(시스템 시계) 하나**로 한다. 시뮬 측정은 시뮬 시계로 하고, 시뮬 숫자에는 "시뮬"을 붙인다. 경계(`>=` / `>`)와 허용 오차를 적는다. 재는 법은 `test-procedure.md`.
- "명령 끊김"의 뜻: **마지막 명령이 0이 아닌데** 정해진 시간 동안 새 명령이 오지 않는다(로봇이 서 있을 때 Nav2가 명령을 멈추는 것은 끊김이 아니다).
- "속도 0"의 뜻: `/joint_states`의 바퀴 속도가 |v| < ___ m/s로 ___번 연속(가정. 멈춰 있을 때의 잡음을 재고 정한다). 고장 ② 때는 이 칸이 마지막 값을 계속 내므로 쓰지 않는다.
- 명령을 보내는 쪽과 주기: ___(teleop 약 10Hz 또는 Nav2 20Hz. 시간 초과 값의 뜻이 주기에 달려 있다. 받침대에서는 Nav2가 돌지 않으니 같은 주기의 고정 명령을 쓴다).

| REQ-STOP-1 | 명령이 끊기면 바퀴가 멈춘다. 재는 구간: 로봇이 마지막 명령을 받은 시각 → 속도 0 | ___ 초 안 | 정상 명령 간격의 최댓값 + 여유. 속도 × 시간 = 멈추기 전 이동 거리 | 실물(받침대 · 바닥) |
| REQ-STOP-2 | 명령이 끊긴 뒤 멈출 때까지 간 거리(바닥 직선, 받은 시각 기준의 마지막 명령 → 속도 0 사이에 간 거리) | ___ cm 안 | 이 프로젝트의 시험 기준(가정). 값 고르기 시험에서 시간 초과 · 최고 속도를 고르는 기준이다 | 시뮬(맞춘 뒤) · 실물(바닥) |
| REQ-FP-1 | 정상 주행 중 잘못 멈추는 횟수 | 10분에 ___회 이하 | 가동률. 시간 초과를 짧게 잡을수록 늘어난다 | 실물 |
| REQ-STALE-1 | OpenCR 읽기가 정해진 시간 동안 실패하면 오류를 알리고 낡은 값을 내보내지 않는다. 재는 구간: 바퀴가 도는 중에 끊고, `/joint_states` 위치 값이 마지막으로 바뀐 메시지의 받은 시각 → 오류 알림 | ___ 초 안 | 읽기 주기(50ms)와 정상 실패 빈도 | 실물(받침대) |
| REQ-DIAG-1 | 고장 상태가 바뀌면 `/diagnostics`에 나온다. 재는 구간: 마지막 명령을 받은 시각(보드 끊김은 위치 값이 마지막으로 바뀐 시각) → `/diagnostics` 상태가 바뀐 메시지를 받은 시각(둘 다 rosbag 안). 발행 방식(주기 · 바뀔 때 바로)을 먼저 정한다(`diagnostic_updater` 기본 1초) | ___ 초 안 | 위쪽 노드와 사람이 고장을 알 수 있어야 한다 | 실물(받침대) |
| REQ-REC-1 | 고장이 풀린 뒤 다시 움직이는 조건(복구 정책). 견줄 것: 새 명령이 오면 바로 움직임 / 잠가 두고 사람이 풀기, 바로 0 / 감속 후 정지 | ___ | ___ | 실물(받침대) |
| REQ-OFF-1 | `cmd_vel_timeout` · `read_timeout`이 0이면 지금 동작과 같다(기능이 꺼진다) | 해당 없음 | 이미 쓰는 사람의 동작을 바꾸지 않는다 | 실물(받침대) |
| REQ-SIM-1 | 시뮬을 실물에 맞춘 뒤, 같은 시나리오(직선 0.15m/s에서 명령 0 · 명령 끊김)에서 실물과의 차이가 정해진 값 안에 든다. 첫째 기준은 시간(명령 → 바퀴 지연 · 계단 응답 · 정지 시간), 둘째는 정지 거리다(0.15m/s에서는 감속 구간이 짧아 거리 차이가 작게 나올 수 있다). 기준은 실물을 재기 전에 정한다 | 시간 ___ms 안 · 정지 거리 ___cm 안(10회 중앙값) | 가정. 시뮬로 시간 초과 · 최고 속도를 먼저 고르려면 이만큼은 맞아야 한다 | 시뮬 · 실물(바닥) |
| REQ-NET-2 | 통신이 나빠지면 알린다: `link_monitor`의 상태가 바뀐다. 재는 구간: 나빠지게 한 시각(`tc netem`을 건 시각, 로봇 시계로 맞춘 값) → `/diagnostics` 상태가 바뀐 메시지 | ___ 초 안 | 가정. 끊기기 전에 사람과 위쪽 노드가 알 수 있어야 한다 | 실물 |

각 요구사항의 시험 · 데이터 · 결과(n/N)는 CI가 `data/`의 CSV에서 추적표로 다시 낸다.
